# Журнал решений

Что и почему решили. Формат записи:

```md
## ГГГГ-ММ-ДД — Короткое название

- **Решение:** что выбрали.
- **Почему:** причина и контекст.
- **Альтернативы:** что рассматривали и почему отбросили.
- **Последствия:** что теперь нельзя/нужно делать иначе.
```

Новые записи — сверху. Записывать сюда стоит то, что дорого восстанавливать из кода: выбор стека, схемы данных, внешних сервисов, договорённости по API, осознанные компромиссы.

## 2026-10-22 — Каркас модуля A: все экраны на мок-адаптере, движение — CSS

- **Решение:** собран Next 15.5.28 (App Router, src/, TS strict) + Tailwind v4 + шрифты Fontsource (Unbounded/Onest). Оболочка (rail/topbar/tabbar), дашборд в компоновке «Пульт», тренировки + карточка, каталог с живым поиском и фильтром, рейтинг с метриками, профиль, login/register. Данные — только через `lib/api-client.ts` с мок-адаптером (задержка 150 мс, чтобы skeleton-состояния были видны). Motion-библиотека не подключена: весь моушен — CSS-классы, унаследованные со стенда (`rise`/`pop`/`fade`, индикатор segmented на `transform`).
- **Почему:** переход между вкладками — это навигация, а навигация занимает main thread; CSS-анимации `transform`/`opacity` уходят на композитор и не падают в кадрах (урок Vercel с таб-индикатором из animation-performance). Мок-адаптер с тем же интерфейсом, что будущий REST, — экраны при подключении API не переписывать.
- **Альтернативы:** `motion/react` с `layoutId` для индикатора навигации — отклонено как раз из-за дропов на маршруте; Recharts сейчас — SVG-графики со стенда портируются один в один и весят ноль, библиотека добавим в модуле B, если понадобится интерактивность.
- **Последствия:** `package.json` фиксирует next 15.5.28, react 19.2, tailwind 4.1; `variants/` остаётся эталоном дизайна до финального выбора; кнопки, которым нужен бэкенд (CRUD, выход из аккаунта), отвечают тостом и помечены «модуль B».

## 2026-10-22 — Дашборд портирован в варианте «Пульт» без финального выбора

- **Решение:** за неимением подтверждённого победителя стенда дашборд собран по «Пульту» (плотная сетка: KPI + график + кольцо цели + донат + достижения + топ рейтинга).
- **Почему:** «Пульт» ближе всех к остальным экранам (карточки, таблицы) и лучше всего смотрится на 1440; оболочка и токены у всех трёх вариантов общие, поэтому замена компоновки — одна страница `dashboard/page.tsx`.
- **Альтернативы:** ждать выбора и делать заглушку — потеря времени; собрать все три — перебор.
- **Последствия:** если заказчик выберет «Витрину» или «Ленту», переписывается только дашборд; рейтинг/тренировки/каталог от выбора не зависят.

## 2026-10-22 — Три варианта главной в статическом стенде

- **Решение:** варианты главной собраны как статический HTML/CSS/JS в `variants/` (свой мини-сервер `node variants/serve.mjs`, порт 4173), а не сразу в Next. Токены, шрифты (локальные woff2 Unbounded/Onest), оболочка приложения и демо-данные там же. Варианты переключаются `?__variant=pult|vitrina|lenta`, стрелками и клавишей `H`.
- **Почему:** кода ещё не было, а выбирать надо глазами и на живом экране с реальными данными. Статический стенд даёт полный контроль над сеткой и графиками (SVG вручную) и не тратит время на scaffold до решения по дизайну.
- **Альтернативы:** сразу собрать три страницы в Next — дольше до первого сравнения; картинки-макеты — нельзя потрогать адаптив и анимации.
- **Последствия:** после выбора победителя вариант переносится в Next/Tailwind/shadcn (графики — Recharts, анимации — Motion), остальные два варианта, пикер и папка `variants/` удаляются. Стенд в git не сдаём.

## 2026-10-22 — Стек: Next.js full-stack, Drizzle + SQLite

- **Решение:** один Next.js 15.5.x (App Router) проект: страницы и REST API в одном процессе. TypeScript strict, Tailwind v4 + shadcn/ui, Motion, Recharts, Drizzle ORM + better-sqlite3, Zod, сессия на `jose` + bcryptjs. Шрифты — Fontsource (Unbounded/Onest).
- **Почему:** 8 часов на всё, 60 % оценки — дизайн и функциональность. Один процесс и один язык убирают CORS, прокси, второй терминал и рассинхрон типов. Route handlers закрывают модуль Б как обычный REST. Готовые компоненты shadcn экономят часы на формах, диалогах и таблицах.
- **Альтернативы:** Vite + React + Express — прозрачнее, но два приложения, CORS и дублирование типов; NextAuth — лишняя настройка; Prisma — кодогенерация и движки, больше точек отказа; JSON вместо БД — допустим по ТЗ, но слабее смотрится в модуле Б и хуже для агрегатов.
- **Последствия:** приложение не разворачивается на Vercel с SQLite — судье достаточно локального запуска и GitHub, как требует ТЗ. Демо-данные обязательны: пустая БД на защите выглядит как недоделка. Если better-sqlite3 не ставится — тот же интерфейс репозитория на JSON-файле, без переписывания экранов.

## 2026-10-22 — Подключён шлюз Claudexia (Qwen)

- **Решение:** кастомный провайдер `claudexia` в глобальном `opencode.jsonc`, две модели — `qwen3.8-max` и `qwen3.8-flash`. Ключ хранится в `headers.Authorization`.
- **Почему:** шлюз OpenAI-совместимый, `/v1/models` отдаёт 57 моделей, включая платные image/video. Кастомный ID провайдера оставляет в списке только эти две. Поле `apiKey` у провайдера в V2 не работает — запросы падали с 401 (проверено).
- **Альтернативы:** `env: ["CLAUDEXIA_API_KEY"]` — работает, но требует рестарта сервиса после смены переменной; провайдер `anthropic` с `baseURL` — тянет весь каталог Claude.
- **Последствия:** ключ лежит открытым текстом в `~/.config/opencode/opencode.jsonc` (вне проекта, в git не попадёт). При смене ключа править этот файл. Дефолтная модель остаётся бесплатной `opencode/deepseek-v4.1-flash-free`.
